# G4 effect-anatomy local pilot

**World:** `vc33-5430563c`  
**Model:** `qwen/qwen3.6-35b-a3b` through OpenRouter, AtlasCloud FP8 only  
**Scope:** G4.0 binding and G4.1 effect anatomy  
**Configuration:** `configs/g4-vc33-openrouter-fast.json`

## Question

After the established G0-G3 path completes, does Duck accept the two G3-ready levers as its only
G4 subjects and explain the controller-compiled effect anatomy for both in human-readable terms?

## Pass conditions

1. G3 again emits a clean inventory containing E0004 and E0005, eight scoped nulls, and no bounded
   unknowns.
2. G4 excludes all scoped null entities and binds exactly the two confirmed levers.
3. Both compiled anatomies report complete coverage and contain no counter cells.
4. Duck submits one accepted `LEVER_EFFECT_ANATOMY` answer per lever.
5. Each explanation names its lever, every effect channel, and every exact observed integer rewrite.
6. The controller emits one `LeverEffectAnatomySet` and stops this slice with deeper G4 questions
   still open.

Game score, level completion, repetition laws, reversibility, conditions, couplings, and winning
are outside this checkpoint.

## Failure classification

- Missing or corrupted evidence binding is an infrastructure failure.
- A rejected answer that omits supplied channel facts is behavioral comprehension friction.
- Exhausting the runtime after the G4 product is emitted is teardown friction, not a gate failure.
- This fast sparse-model result does not substitute for the dense Qwen3.6 rehearsal.
