## Second-belief-writer risks

1. **Highest risk: two independent `world_model` pipelines already exist.** The gate `TargetJournal` is the ratified belief writer, while `VirelaiRuntime._canonical_world_model()` independently infers roles/mechanics from the passive observer journal and writes `world_model.json`. Reusing that file name without changing its source would make the observer compiler a second belief writer.
2. **Two player-card families exist.** `card_builder.build_card()` is gate-derived; `virelai_memory_card.build_memory_card()` is observer-world-model-derived. The new library digest should be added to the former and use the latter only as a presentation template.
3. **The lazy G3 ledger is an identity integrator, not a semantic authority.** A separate entry-shell segmenter could create competing IDs. The safe design is an entry census namespace with explicit reconciliation/provenance to later G3 IDs; no silent merge and no role certification from appearance.
4. **Golden Band-1 and role readers are prior art, not current products.** Their outputs may populate diagnostic fields only after a specific gate-record projection is adopted and graded. They cannot silently become certified roles.

## WO-L2a consequence

WO-L2a can proceed without changing any gate semantics, but it needs three new read-only components: an ENTRY census shell, a reconciler onto the lazy G3 ledger, and a canonical gate-derived compiler/card projection. A small lifecycle hook is likely required immediately before `_advance_level` rebuilds level state and at run end. That hook touches shared runtime code and therefore needs its own shared-file note and fail-first early-stop/boundary tests.
